## 1.1 选择问题（第 k 大元素）

**题目要点**：给定 N 个数，求第 k 大的元素；要求至少给出两种算法并比较运行时间。

**三种解法与复杂度**（实现见 `ch02_algorithm_analysis/kth_largest.c`，测试见 `tests/test_ch02.c`）：

| 解法 | 时间 | 额外空间 | 是否改变输入 |
|------|------|----------|--------------|
| 排序后取第 k 个（插入/冒泡/`qsort`） | O(N log N)（插入排序对一般数据是 O(N²)） | O(1) | 是 |
| 维护大小为 k 的最小堆 | O(N log k)，k≪N 时接近 O(N) | O(k) | 否 |
| 快速选择（quickselect） | 平均 O(N)，最坏 O(N²) | O(1) | 是 |

**关于运行时间表格的结论**（这是本题的重点）：
- N ≤ 10^4 时三种方法都很快，看不出差别；
- N = 10^5 ~ 10^6 时，O(N log N) 排序大约是 O(N) 快速选择的 log N ≈ 17~20 倍；
- k 很小（如 k=10）而 N 很大时，大小为 k 的堆是工程上最稳的选择：单遍扫描、不破坏输入、最坏情况也是 O(N log k)。
- 快速选择的最坏情况 O(N²) 出现在每次划分极不均衡时（已排序输入 + 取末元素作枢轴），
  用「三数取中」或随机枢轴可把最坏情况概率压到可忽略。

**为什么下界是 Ω(N)**：任何正确算法都必须至少读一遍输入（否则未被读到的元素可能才是答案），
所以 O(N) 已是渐近最优；快速选择达到这个下界。

## 1.2 单词谜题 / 网格找词（编程题）

**题目要点**：在 R×C 的字母方阵中，找出给定单词表中所有出现的单词；单词可沿 8 个方向
（横、竖、两个对角线，各含正反）连续出现。

**解法**：对每个单词 w（长度 L），枚举每个起点 (r,c) 与 8 个方向，逐字符匹配。

- 时间：O(W · R · C · L)（W 为单词数），每个起点最多做 L 次比较；
- 空间：O(R·C)（存字符方阵）+ O(L)（比较缓冲）。
- 优化：先把单词表按首字母分桶，只从匹配首字母的位置出发，常数会显著下降；
  若单词表很大，可换成对每个起点沿 8 个方向生成长度为 maxL 的字符串，
  再放入哈希表/字典树匹配，可做到与 L 无关的平均匹配代价。

## 1.3 递归与归纳（数学复习题）

**核心方法**：证明关于递归程序的命题，标准套路是对「递归深度/参数规模」做归纳：

1. **基例**：验证最小规模（通常是 N=0 或 1）成立；
2. **归纳假设**：假设所有规模 < N 的调用都满足命题；
3. **归纳步骤**：把规模 N 的调用改写成若干次更小的调用，代入归纳假设化简。

**关于「递归四法则」**（教材 1.3 节的基础性结论，本章习题常考）：

1. **基准情形**：必须有不用递归就能直接求解的情形；
2. **不断推进**：每次递归调用都必须朝基准情形靠近；
3. **设计法则**：假设所有更小的调用都能正确工作（不要试图追踪整个调用链）；
4. **合成效益法则**：不要在递归调用的不同分支里做重复的工作——这正是 Fibonacci
   朴素递归 O(φ^N) 与记忆化 O(N) 的区别（见 `ch02_algorithm_analysis/fibonacci.c`）。

## 1.4 数学复习中的常用结论（习题反复用到）

| 结论 | 说明 |
|------|------|
| 2^N > N^2 （N ≥ 5） | 指数增长最终压倒任何多项式；可用归纳证明 |
| log(AB) = log A + log B | 换底、拆分的依据 |
| log(A^B) = B log A | 常用来化简 log(N²) = 2 log N |
| log X < X（对所有 X > 0） | 对数增长慢于线性 |
| ⌊log2 N⌋ + 1 | 二进制表示 N 所需的**位数**，也是「反复折半」的步数 |
| X^Y 的二进制表示位数 ≈ Y log2 X | 用于估计算术运算的规模上界 |
| 几何级数 Σ_{i=0}^{N} 2^i = 2^{N+1} − 1 | 扩容（倍增）摊还分析的基石 |
| Σ_{i=1}^{N} (1/i) = Θ(log N) | 调和级数，用于「自顶向下」复杂度估计 |

**递推式的常用解法**：代入法（先猜阶，再归纳验证）、递归树（求每层代价与层数）、
主定理（T(N) = aT(N/b) + Θ(N^k) 三种情形）。
