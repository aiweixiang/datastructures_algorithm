## 2.1 按增长率排列给定函数

把给定函数按增长率**从小到大**排列，并指出同阶者：

```
2/N  <  37  <  √N  <  N  <  N log log N  <  N log N ≈ N log(N²)  <  N log²N
     <  N^1.5  <  N²  <  N² log N  <  N³  <  2^(N/2)  <  2^N
```

**关键理由**：

- `N log(N²) = 2 N log N`，与 `N log N` **同阶**（常数因子不计）；
- `log N < √N`（对足够大的 N）⇒ `N log²N < N·N^0.5 = N^1.5`；
- `N² log N` 与 `N²` **不同阶**（多一个无界因子），但都小于 `N³`；
- `2^(N/2) = (√2)^N`，与 `2^N` 同为指数增长但底数更小，故 `2^(N/2) < 2^N`；
- `2/N` 递减趋于 0，比常数 37 还小。

**方法论**：两个函数的相对增长速度看 `lim_{N→∞} f(N)/g(N)`：
0 ⇒ f = o(g)；常数 ⇒ 同阶；∞ ⇒ f 增长更快；不存在 ⇒ 不可比（见 2.5）。

## 2.2 判断大 O 记号是否成立

判据：`f(N) = O(g(N))` ⟺ `lim sup_{N→∞} f(N)/g(N) < ∞`（即存在常数 c 与 N₀，
使 N ≥ N₀ 时 f(N) ≤ c·g(N)）。

| 断言 | 是否成立 | 理由 |
|------|----------|------|
| `N log N = O(N²)` | ✅ | 比值 `log N / N → 0` |
| `N² = O(N log N)` | ❌ | 比值 `N / log N → ∞` |
| `2^N = O(N^k)`（任意常数 k） | ❌ | 指数压倒多项式，比值 → ∞ |
| `log N = O(√N)` | ✅ | 令 X = √N，由 `log X < X` 得 `log N = 2 log √N < 2√N` |
| `N = O(N log N)` | ✅ | 比值 `1/log N → 0` |
| `f = O(f)`（任何 f） | ✅ | 取 c = 1；这就是"≤"的自反性 |

**易错点**：大 O 是**上界**，不是"最优界"。说 `N = O(N²)` 也没错，
只是不紧（tight）；表达紧界要用 Θ。常数因子和低阶项可以丢掉：
`3N² + 100N + 7 = Θ(N²)`。

## 2.3 比较两个函数的增长速度

用同一个极限判据，配合 2.4 的结论：

| 对比 | 结论 | 方法 |
|------|------|------|
| `log N` vs `log²N` | `log N = o(log²N)` | 令 u = log N，比较 u 与 u² |
| `N log N` vs `N^1.5` | `N log N = o(N^1.5)` | 比值 `log N / √N → 0` |
| `2^N` vs `N!` | `2^N = o(N!)` | 比值含 `(N/2)^(N/2)` 因子，趋于 0 |
| `N!` vs `N^N` | `N! = o(N^N)` | 逐项比较 `i ≤ N`，且至少一半项 ≤ N/2 |
| `log(N!)` vs `N log N` | **同阶** | Stirling：`log(N!) = N log N − N + O(log N)` |
| `N^log N` vs `2^N` | 取对数后比 `log²N` 与 `N`：`N^log N = o(2^N)` | 两边取 log |

`log(N!) = Θ(N log N)` 这条结论后面反复用到（比较排序的下界、决策树深度）。

## 2.4 证明 log^k N = o(N)

**证明**：只需证 `lim_{N→∞} log^k N / N = 0`。

在 1.5 的结论 `log X < X`（∀X > 0）中取 `X = N^(1/(k+1))`：

```
log N^(1/(k+1)) < N^(1/(k+1))
⇒  (1/(k+1)) log N < N^(1/(k+1))
⇒  log N < (k+1) N^(1/(k+1))
```

两边取 k 次方得 `log^k N < (k+1)^k · N^(k/(k+1))`，于是

```
log^k N / N  <  (k+1)^k · N^(k/(k+1) − 1)  =  (k+1)^k · N^(−1/(k+1))  →  0
```

所以 `log^k N = o(N)`。∎

**另一种证法**：对 `log^k N / N` 用 k 次洛必达法则，每次分子降一阶、分母仍为 N，
最终得到 `k! / N → 0`（更简洁但依赖连续性/可导）。

## 2.5 构造互不为大 O 的函数对

要 `f(N) ≠ O(g(N))` 且 `g(N) ≠ O(f(N))`，即 `f/g` 无界且 `g/f` 无界。

**构造一（按奇偶交替）**：

```
f(N) = N²   (N 为偶数)，  f(N) = N    (N 为奇数)
g(N) = N    (N 为偶数)，  g(N) = N²   (N 为奇数)
```

则沿偶数 N，`f/g = N → ∞`（f 不是 O(g)）；沿奇数 N，`g/f = N → ∞`（g 不是 O(f)）。
两者都无界 ⇒ 互不为大 O。∎

**构造二（振荡指数）**：`f(N) = N`，`g(N) = N^(1 + (−1)^N · 1/2)`。
偶数 N 时 g = N^1.5，奇数 N 时 g = N^0.5，于是两个方向的比值都出现无界的情形。

**结论**：大 O 是**偏序**而不是全序——存在不可比的函数对。
这也说明「按增长率排序」只对给定的一组具体函数有意义（如 2.1），
不能指望任意两个函数都能比较。

## 2.6 分析 6 段代码的运行时间

方法是把「循环嵌套」翻译成乘积、「索引倍增/折半」翻译成 log、「递归」翻译成递推式。
下面用 6 个代表性模式（对应教材那 6 段代码的典型形态）：

| # | 形态 | 复杂度 | 推导 |
|---|------|--------|------|
| 1 | `for i: for j: 常数操作` | O(N²) | 内层次数 N·N |
| 2 | `for i: for j = i: 常数操作` | O(N²) | 次数 `N(N+1)/2 = Θ(N²)`（常数 1/2 不计） |
| 3 | `for i = 1; i < N; i *= 2` | O(log N) | 变量倍增，次数 ⌈log₂N⌉ |
| 4 | `for i: for j = 1; j < N; j *= 2` | O(N log N) | 外层 N，内层 log N |
| 5 | `for i: for j: for k: 常数操作` | O(N³) | 三层乘积 |
| 6 | `f(N) = f(N/2) + O(1)` 递归 | O(log N) | 每次规模折半 |

**注意三种"看起来像 N² 但其实是 N log N 或 N√N"的情况**：

- 内层循环上界是 `N/i`（如 `for j = 1; j <= N/i; j++`）⇒ Σ N/i = N·H_N = O(N log N)；
- 内层上界是 `√N` ⇒ O(N√N)；
- 内层是 `j = i; j < N; j += i` ⇒ Σ N/i 的调和形式 ⇒ O(N log N)（筛法就是这种）。

## 2.7 分析三种生成随机置换的算法

代码：`permutations.c`；测试：`tests/test_ch02.c`（统计检验 + **精确枚举**）。

| 算法 | 做法 | 是否均匀 | 时间复杂度 |
|------|------|----------|-----------|
| A 拒绝采样 | 反复取随机数直到取到未用过的 | ✅ 均匀 | **期望** O(N log N) |
| B 与任意位置交换 | i 从 0..N−1，与 `random(0..N−1)` 交换 | ❌ **不均匀** | O(N) |
| C Fisher–Yates | i 从 0..N−1，与 `random(i..N−1)` 交换 | ✅ 均匀 | O(N) |
| D 直接赋值 | `a[i] = random(N)` | ❌ 根本不是置换 | O(N) |

**A 的期望代价**：填第 i 个位置时"击中未用值"的概率是 `(N−i)/N`，
所以期望抽取次数是 `N/(N−i)`；总和为
`Σ_{i=0}^{N−1} N/(N−i) = N·H_N ≈ N ln N = O(N log N)`
（H_N 是调和级数，见 1.7）。注意最坏情况是"无穷次"，但概率为 0。

**C 的均匀性证明**（最干净）：第 i 步有 `N − i` 种选择，总选择序列数是
`N·(N−1)···1 = N!`；且**每个选择序列对应唯一一个最终置换**（双射），
所以每个置换恰好由一条序列产生，概率都是 `1/N!`。∎

**B 为什么不均匀**（本仓库纠正的一个常见错误结论）：
B 共有 `N^N` 条等概率的选择序列，每个置换的概率必然是 `1/N^N` 的整数倍；
要均匀就必须 `N! | N^N`。但 N = 3 时 `27` 不是 `6` 的倍数，
N = 4 时 `256` 不是 `24` 的倍数……所以 **N ≥ 3 时 B 必定不均匀**（N = 2 是巧合成均匀）。

**N = 3 时 B 的精确分布**（`tests/test_ch02.c` 枚举全部 27 条序列验证）：

| 置换 | 012 | 021 | 102 | 120 | 201 | 210 |
|------|-----|-----|-----|-----|-----|-----|
| 次数 | 4 | 5 | 5 | 5 | 4 | 4 |
| 概率 | 4/27 | 5/27 | 5/27 | 5/27 | 4/27 | 4/27 |

（这就是经典的「朴素洗牌陷阱」：代码看起来对称，其实有偏。）

**结论**：需要随机置换时一律用 **Fisher–Yates**。

## 2.8 估算最大子序列和算法运行时间

四种实现的代码见 `max_subsequence_sum.c`。设每次内层基本操作耗时为 t：

| 算法 | 操作次数 | N = 10³ | N = 10⁴ | N = 10⁵ |
|------|----------|---------|---------|---------|
| 立方 O(N³) | ≈ N³/6 | 1.7×10⁸ | 1.7×10¹¹ | 1.7×10¹⁴ |
| 平方 O(N²) | ≈ N²/2 | 5×10⁵ | 5×10⁷ | 5×10⁹ |
| 分治 O(N log N) | ≈ N log₂N | 10⁴ | 1.3×10⁵ | 1.7×10⁶ |
| 线性 O(N) | N | 10³ | 10⁴ | 10⁵ |

**结论**：N = 10⁵ 时立方算法需要约 10¹⁴ 次操作（即使每次 1ns 也要一天以上），
而线性算法只要 10⁵ 次（微秒级）——**差 9 个数量级**。
这正是教材用这道题演示"算法选择比机器快慢重要得多"的原因。

**分治的递推式**：`T(N) = 2T(N/2) + O(N)` ⇒ 递归树每层总代价 N、共 log₂N 层 ⇒ O(N log N)。

## 2.9 / 2.10 多项式求值与 Horner 法则

设 N 次多项式（N+1 个系数），代码：`horner.c`。

| 方法 | 乘法次数 | 加法次数 | 复杂度 |
|------|----------|----------|--------|
| 朴素：每项重算 x^i | `Σ_{i=1}^{N} i = N(N+1)/2` | N | **O(N²)** |
| 逐项递推求 x^i（保存上一次的幂） | N | N | O(N) |
| **Horner 法则** | **N** | **N** | **O(N)** |

Horner（2.10）：把多项式改写成
`a_N x^N + … + a_1 x + a_0 = ((…(a_N x + a_{N−1})x + a_{N−2})x + …)x + a_0`，
每步只有一次乘法一次加法，不需要单独计算任何 x 的幂。
测试对拍：随机系数下 Horner 与朴素求值结果一致（容差 1e-6），
并固定验证 `1 + 2x + 3x²` 在 x = 2 时为 17。

## 2.11 判断数组中是否存在 A[i] = i

代码：`fixed_point.c`（0 起始与 1 起始两种写法）。

**关键不变量**：数组严格递增时，`f(i) = A[i] − i` 是**非减**的：
`A[i+1] > A[i] ⇒ A[i+1] − (i+1) ≥ A[i] − i`。
于是可以二分：

- `A[mid] == mid` → 找到；
- `A[mid] < mid` → 左侧不可能有不动点（f 非减且此处已 < 0），向右找；
- `A[mid] > mid` → 向右找。

时间 O(log N)、空间 O(1)。测试用 800 组随机严格递增数组与线性扫描对拍，
并覆盖了「0 起始有解、1 起始无解」这类下标约定差异。

> 注意题目若是 1 起始写法（求 i 使 `A[i] == i`，i ∈ [1,N]），
> 只要把比较改成 `a[mid] == mid + 1`。**下标约定必须先和题意对齐**，
> 这是本题最容易扣分的地方。

## 2.12 最小子序列和 / 最小正子序列和 / 最大子序列乘积

代码：`subsequence_variants.c`。

**(a) 最小子序列和（允许空段）**：把最大子序列和的判据整体反向——
累加时若 `this_sum > 0` 就把已正的前缀丢弃（正前缀只会抬高水平线）。
O(N) 时间、O(1) 空间。

**(b) 非空最小子序列和**：`dp[i] = min(a[i], dp[i−1] + a[i])`，O(N)。
与 (a) 的区别只在「是否允许空段」：全正数组时 (a) 给 0、(b) 给最小元素。

**(c) 最小正子序列和**：定义 `prefix[j] = a[0..j−1]`，则
答案 = `min{ prefix[j] − prefix[i] > 0 : i < j }`。
对每个 j，只需在「之前出现过的所有前缀和」中找**小于 prefix[j] 的最大者**。
这需要一个**有序集合**（第 4 章的平衡树 / 第 12 章的 treap），
插入与查找各 O(log N) ⇒ **O(N log N)**。
本仓库给出 O(N²) 的直接枚举版本作为可验证的参考实现。

**(d) 最大子序列乘积（非空连续）**：因负数会"把最小翻成最大"，
需要同时维护两个候选：`cur_max` 与 `cur_min`，转移时用
`{x, cur_max·x, cur_min·x}` 的最大/最小值更新。
O(N) 时间、O(1) 空间。测试对拍 400 组小数组的 O(N²) 暴力参考，
并覆盖 `{2,3,-2,4} → 6`、`{-2,-3,-1} → 6`、`{-3,-1,-7} → 7`、`{0,2} → 2`。
（注意 `{2,3,-2,4}` 的答案不是乘积最大的"看起来那种"，必须真算。）

## 2.13 编写并分析素数判定程序

代码：`is_prime`（`primes.c`）。

**算法**：先处理 2（唯一偶素数），再对所有奇数 d 试除到 `√N`。

**分析与优化**：
- 时间 `O(√N)`：若 N = a·b 且 a ≤ b，则 a ≤ √N，所以只需试到 √N；
- 只需试素数（但那样需要先筛出素数，反而更贵）；
- 循环条件写成 `d <= n / d` 而不是 `d * d <= n`，避免 `d*d` 溢出；
- **更大的 N**：试除法对 N ≈ 10¹⁸ 需要约 10⁹ 次除法（数分钟），
  实际用**概率型**算法（Miller–Rabin，第 10 章"随机化算法"）
  或确定性算法（AKS）；数学软件对小 N 用试除 + 筛。

测试：与筛法在 [0, 20000] 上全量对拍（0 处不一致），
并验证 10⁹+7、10⁹+9、999999937 是素数、10⁹+5 不是。

## 2.14 分析 Eratosthenes 筛法的运行时间

代码：`sieve_primes`、`sieve_collect`（`primes.c`）。

**算法**：从 2 开始，把每个素数的倍数（从 i² 起）标记为合数。
从 `i²` 开始可以避免重复标记更小的倍数。

**复杂度推导**：

```
时间 = Σ_{p ≤ N, p 素数}  (N − p²)/p + O(N)  ≈  N · Σ_{p ≤ N} 1/p
     = N · (ln ln N + M)   ← 梅尔滕斯定理
     = O(N log log N)
```

其中 `Σ_{p≤N} 1/p` 是"素数调和级数"，它虽然发散但**发散得极慢**
（N = 10⁹ 时才约 3.3）。所以筛法几乎是线性的。

**空间** O(N)：用字节数组最简单；用**位图**可以省 8 倍；
只存奇数（跳过偶数）再省一半，合起来常数可达 16 倍优化。

测试：π(10)=4、π(100)=25、π(1000)=168、π(10⁴)=1229、π(20000)=2262，
并与试除法全量对拍。

## 2.15 证明 X^62 只需 8 次乘法

**构造性的加法链**（每行一次乘法）：

| 步骤 | 结果 | 乘法次数 |
|------|------|----------|
| 1 | `x2 = x·x` | 1 → x² |
| 2 | `x3 = x2·x` | 2 → x³ |
| 3 | `x5 = x3·x2` | 3 → x⁵ |
| 4 | `x10 = x5·x5` | 4 → x¹⁰ |
| 5 | `x20 = x10·x10` | 5 → x²⁰ |
| 6 | `x30 = x20·x10` | 6 → x³⁰ |
| 7 | `x31 = x30·x` | 7 → x³¹ |
| 8 | `x62 = x31·x31` | 8 → **x⁶²** |

所以 8 次乘法足够（代码 `pow62_optimal`，测试断言 `pow62_optimal(x) == pow_fast(x,62)`）。

**一个通用下界**：m 次乘法最多把指数从 1 翻到 `2^m`（每步最多把一个已有指数翻倍），
要得到 62 需 `2^m ≥ 62` ⇒ `m ≥ ⌈log₂62⌉ = 6`。所以 8 在 [6, 8] 区间内。
（精确的加法链长度 l(62) 属于"最优加法链"问题，与 2.17 的二进制幂对比时值得讨论：
二进制幂需要 10 次，可见**它不总是最优**。）

## 2.16 写出非递归快速求幂

代码 `pow_fast`（`power.c`）与 `pow_binary_count`（`pow_chain.c`）：

```c
long long pow_fast(long long x, int n) {
    long long result = 1;
    while (n > 0) {
        if (n & 1) result *= x;   /* 当前二进制位为 1 → 乘进结果 */
        x *= x;                   /* 指数减半 ⇒ 底数平方 */
        n >>= 1;
    }
    return result;
}
```

**为什么等价于递归版**：递归版是 `x^n = (x²)^(n/2)`（n 偶）或 `x·(x²)^((n−1)/2)`（n 奇）；
迭代版正是把这个「平方 + 右移」的过程自底向上摊平，把"哪一步需要乘 x"
改由 N 的二进制位决定。时间 O(log N)、空间 O(1)（递归版需要 O(log N) 栈）。

## 2.17 精确计算快速求幂的乘法次数

采用「跳过最后一次无用平方」的实现约定，代码 `pow_binary_count`：

```
乘法次数 = ⌊log₂ N⌋ + popcount(N)
          └─ N 次平方 ─┘  └─ 每位为 1 时乘一次 x ─┘
```

**验证**：`tests/test_ch02.c` 对 N = 1..1000 逐个数出实际乘法次数与公式比对（全部一致），
并单独断言 N = 62 时为 **5 + 5 = 10** 次。

**关于约定**：如果把最高位那次"乘 x"省掉（先把结果初始化成 x），
就得到 `⌊log₂ N⌋ + popcount(N) − 1`；两种约定只差最高位那一次。
**写这道题时必须说明自己用的是哪种约定**，否则答案会和标准答案差 1。

**对比 2.15**：x⁶² 的二进制幂要 10 次，而最优加法链只要 8 次——
所以「快速求幂」是 O(log N) 的**上界**，不是最优乘法的下界。

## 2.18 比较两个程序的最坏/实际运行时间

分析要区分四种"运行时间"：

| 概念 | 含义 | 典型差别 |
|------|------|----------|
| 最坏情况 W(N) | 所有规模 N 的输入中最慢的 | 快速排序 O(N²)（已排序输入） |
| 平均情况 A(N) | 在某个输入分布下的期望 | 快速排序 O(N log N) |
| 最好情况 B(N) | 最幸运的输入 | 插入排序 O(N)（已有序） |
| 实际/经验运行时间 | 在具体机器与数据上的测量值 | 受缓存、常数、编译器优化影响 |

**结论**：
1. 渐近同阶不代表实际时间相同（常数因子、局部性差异可达 3~10 倍）；
2. 最坏情况与平均情况可能**差一个数量级甚至一个幂次**（快排、哈希）；
3. 大 O 常数在 N 较小时可能被低阶项主导，所以"小 N 用法则"（如插入排序）
   在实践中仍有价值（这也是标准库对小数组切换到插入排序的原因）；
4. 报告性能时必须说明是哪种度量，否则不可比。

## 2.19 寻找出现次数超过 N/2 的主要元素

代码：`majority.c`（Boyer–Moore 投票）。

**算法**：维护候选者 candidate 与计数 count；遇到相同元素 count+1，
不同则 count−1，count 归零时换候选者。最后**再扫一遍验证** candidate 的出现次数 > N/2。

**正确性（若多数元素存在则一定被留下）**：把"多数元素"与"非多数元素"两两配对抵消。
设多数元素出现 m > N/2 次，非多数元素 N−m < m 次。
每次抵消消耗一个元素，最坏情况下也只会消耗掉 N−m 个多数元素，
剩下 `m − (N−m) = 2m − N > 0` 个多数元素未被抵消，所以候选者必是它。∎

**为什么必须验证**：当不存在多数元素时，算法仍会返回一个候选者
（如 `[1,2,3]` → 候选者 3，出现 1 次 ≤ 3/2）。所以验证扫描是不可省略的，
总代价仍是 O(N) 时间 / O(1) 空间。

**其他答案**：排序后取中间元素再验证 O(N log N)（但需要能修改输入或 O(N) 副本）；
哈希计数 O(N) 时间但 O(N) 空间。投票法在空间上最优。

测试：600 组随机数组（一半注入多数元素并用 Fisher–Yates 打散布局）与暴力计数对拍。

## 2.20 解释整数固定长度假设的重要性

教材的绝大多数分析都建立在「**word-RAM 模型**」上：假定整数占固定字长（如 64 位），
四则运算和比较都是 **O(1)**。这个假设不是天然成立的：

1. **不设固定长度时，算术不再是 O(1)**。n 位数加法是 O(n/word)，乘法是
   O((n/word)^1.58) 或更好；`N!` 需要 Θ(N log N) 位，
   所以「算 N! 是 O(N) 次乘法」这种说法必须区分**字运算次数**与**位运算次数**；
2. **溢出会改变算法正确性**。例如 2.15 里 x⁶² 用 64 位整数算 x = 3 就会溢出
   （3⁶² ≈ 3.8×10²⁹ ≫ 9.2×10¹⁸），正确性被静默破坏——
   这正是"固定长度"带来的实际约束，而不是数学问题；
3. **排序下界的讨论也依赖模型**。比较排序的 Ω(N log N) 是**比较模型**下的结论；
   允许对 O(1) 位整数做非比较操作时，可以做到 O(N)（基数排序、桶排序）；
4. **大 O 的"隐藏常数"随字长增长**。字长翻倍时所有常数都变，渐近分析不变但常数变了。

**结论**：报告复杂度时必须写明模型。教材默认「固定字长 + O(1) 算术」，
所以第 1.8 题（2¹⁰⁰ mod 5）这类题才必须靠**模运算**把中间结果限制在固定字长内。

## 2.21 分析字谜游戏算法并用二分优化

**基础解法**（第 1 章 1.2，代码 `ch01_introduction/word_puzzle.c`）：
对每个单词 W（长度 L）枚举每个起点与 8 个方向，
`O(W · R · C · L)` 时间。

**用二分优化的正确姿势**：这里不能直接对"单词"二分，
因为匹配方向是二维的。可行的三条优化路线：

1. **先排序单词表，再对每个候选串二分**：枚举每个起点与方向生成长度 ≤ Lmax 的串，
   对每个前缀长度在**排序后的单词表**里二分查找，代价
   `O(R·C·8·Lmax·log W)`；当 W 很大、Lmax 很小时优于基础解法；
2. **按首字母（或前两个字母）分桶**：常数级加速，实现最简单，
   把"对每个单词扫全表"变成"只从可能的首字母出发"；
3. **字典树（trie）/哈希表**：把所有单词建 trie，从每个起点沿 8 个方向往下走，
   命中即输出，总代价 `O(R·C·8·Lmax)`，与 W 无关——**这是本题的最优答案**
   （trie 在第 5 章/第 12 章相关章节讨论）。

**结论**：二分能优化的前提是"存在一个有序的一维搜索空间"。
本题的关键是把二维枚举**转成一维前缀串**之后，二分（或 trie）才有效。

## 2.22 修改二分查找边界判断是否正确

这是「差一错误（off-by-one）」的经典题。列出常见改动及其后果
（`a` 升序，N 个元素，查找 x）：

| 改法 | 后果 |
|------|------|
| `mid = (low + high) / 2` | 当 `low + high` 溢出 int 时 mid 变负 → **越界访问**（应写 `low + (high−low)/2`） |
| `low = mid`（应为 `mid+1`），循环条件 `low <= high` | 区间不缩小 → **死循环** |
| `high = mid`（应为 `mid−1`），循环条件 `low <= high` | 死循环 |
| 循环条件 `low < high` + `low = mid+1` / `high = mid` | **正确**（这是 lower_bound 形态，但循环后需一次确认比较，见 2.23） |
| 循环条件 `low < high` + `low = mid` / `high = mid−1` | 死循环或漏查 |
| `high = n`（应为 `n−1`）而 mid 比较用 `a[mid]` | 首轮可能访问 `a[n]` → 越界 |
| `high = n−1` 但循环条件写 `low < high` | 不检查最后一个元素 → 可能**漏报** |
| 与 `>` 反着写（降序数组用升序逻辑） | 语义全错，但可能"看起来能跑" |

**正确的两种范式（记住这两条就不会错）**：

```c
/* 范式一：闭区间 [low, high]，循环 low <= high，比较两次 */
while (low <= high) { mid = low+(high-low)/2;
    if (a[mid] < x) low = mid+1; else if (a[mid] > x) high = mid-1; else return mid; }
/* 范式二：半开区间 [low, high)，循环 low < high，比较一次 */
while (low < high) { mid = low+(high-low)/2;
    if (a[mid] < x) low = mid+1; else high = mid; }
```

**检验方法**：对每个 N、每个 x 与线性扫描对拍（本仓库 `tests/test_ch02.c` 就是这么做的，
`n = 0..30`、`x ∈ [−1, 2n+1]` 全覆盖）。**不要靠"看起来对"来验证边界。**

## 2.23 实现每次只做一次比较的二分查找

代码：`bisect_one_compare_count`（`binary_search.c`）。

**做法**：循环体内**只判断 `a[mid] < x`**（一次比较），
把「等于」和「大于」合并处理（`high = mid`），循环结束后再做一次确认比较。

```c
while (low < high) {
    mid = low + (high - low) / 2;
    if (a[mid] < x) low = mid + 1;      /* 唯一的一次比较 */
    else            high = mid;
}
return (a[low] == x) ? low : NotFound;  /* 收尾的一次 */
```

**复杂度**：循环内比较次数 ≤ `⌈log₂N⌉`，加收尾一次 ⇒ 总计 ≤ `⌈log₂N⌉ + 1`；
而经典两比较写法最坏约 `2⌊log₂N⌋ + 2` 次。**约省一半比较次数**。

**代价**：返回的是"第一个等于 x 的位置"（lower_bound 一旦命中），
不能像经典写法那样"任意一个位置"；若题目要求"任意一个"，需要额外定位。
测试断言：结果与经典 `bisect` 完全一致（`n ≤ 40`、全部 x 全覆盖），
且比较次数不超过 `⌈log₂N⌉ + 1`。

## 2.24 修改最大子序列和分治代码是否正确

分治的正确结构（代码 `mss_divide_conquer`）：

```
best = max3( 跨越中点的最大和,          ← 左半后缀最大 + 右半前缀最大
             左半递归结果,
             右半递归结果 )
```

**常见改动及其对错**：

| 改动 | 是否正确 | 原因 |
|------|----------|------|
| 漏掉 `max3` 中的两个递归结果，只返回跨越和 | ❌ | 最优解可能完全落在某一半内部 |
| 右半前缀循环从 `center` 开始（而非 `center+1`） | ❌ | `a[center]` 被两边各算一次，跨越和被高估 |
| 左半后缀循环从 `center-1` 开始 | ❌ | 同上，`a[center]` 被漏掉或重复 |
| 两个累加器初始化为 0（而不是 `a[center]`） | ✅ | 正是"允许空后缀/空前缀"的实现方式，与空子序列约定一致 |
| 基例返回 `a[left]` 而不夹到 ≥ 0 | ❌ | 会破坏"空子序列可取 0"的约定，全负数时应返回 0 |
| 基例写成 `left > right` | ❌ | 会漏调用于单元素区间的情形；正确基例是 `left == right` |
| `center = (left+right)/2` | ⚠️ | 数学上正确，但 `left+right` 可能溢出；用 `left+(right-left)/2` |
| 把 `max3` 写成 `max` 的两次嵌套但顺序写错 | ⚠️ | 顺序不影响 `max` 的结果，只影响可读性 |

**统一验证方法**：与 O(N²) 暴力参考实现在随机数组上对拍
（本仓库对 300 组随机数组、长度 ≤ 45、取值 ∈ [−25,25] 全量对拍四种算法）。

## 2.25 解释立方与平方算法迭代次数差异

代码：`mss_cubic_iterations` / `mss_quadratic_iterations`（`subsequence_variants.c`）。

**立方算法**（枚举 i、j、再求 i..j 的和）内层语句执行次数：

```
Σ_{i=0}^{N−1} Σ_{j=i}^{N−1} (j − i + 1) = Σ_{i} (N−i)(N−i+1)/2 = N(N+1)(N+2)/6 = Θ(N³)
```

**平方算法**（枚举 i、j 时复用累加结果）内层语句执行次数：

```
Σ_{i=0}^{N−1} (N − i) = N(N+1)/2 = Θ(N²)
```

**两者之比**：

```
[N(N+1)(N+2)/6] / [N(N+1)/2] = (N+2)/3 ≈ N/3
```

**结论**：平方算法不只是"少一层循环"，它把内层的**求和**换成了 O(1) 的累加，
次数比约为 N/3。N = 10⁴ 时立方算法约 1.7×10¹¹ 次、平方算法约 5×10⁷ 次——相差 3000 多倍，
这就是"消除一层循环内的重复计算"带来的收益。

测试：对 N = 0..60 逐个用**实际循环计数**与上面的闭式公式比对（全部一致）。
