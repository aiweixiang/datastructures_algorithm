# 第 3 章 表、栈和队列 —— 习题解答

> 编号按第 2 版；每处同时标注主题。实现分别在同目录下各 `.c` 文件，
> 由 `tests/test_ch03.c`（713 条断言）验证。

## 本章核心结论：三种表实现的取舍

| 操作 | 顺序表（数组） | 单链表（带头结点） | 游标（数组模拟链表） | 双链表（带哨兵） |
|------|----------------|--------------------|----------------------|------------------|
| `Find(x)` | O(N) | O(N) | O(N) | O(N) |
| `FindKth(k)` | **O(1)** | O(N) | O(N) | O(min(k, N−k)) |
| `Insert`（已知位置） | O(N)（元素后移） | **O(1)** | **O(1)** | **O(1)** |
| `Delete`（已知结点） | O(N) | O(N)（需前驱） | O(N) | **O(1)** |
| 额外空间 | 可能预留过量 | 每元素 1 个指针 | 每元素 1 个索引 + 固定空间池 | 每元素 2 个指针 |
| 扩容/溢出 | 需要 realloc（倍增） | 无上限 | **会真正溢出**（空间池用尽） | 无上限 |
| 主要优点 | 随机访问、缓存友好 | 插入删除灵活 | 无指针/可持久保存到文件 | 双向遍历、删除 O(1) |

**要点答案**：
1. **为什么单链表带一个「头结点」**：把「在第一个位置插入/删除」这一特殊情况消掉，
   所有 `Insert` 都变成「在某个结点之后插入」，代码无需分支判断（见 `list_linked.c`）；
2. **游标实现的意义**（`list_cursor.c`）：在没有指针、或需要把结构整体持久化到文件/
   共享内存的场景下，用数组下标代替指针；`space[0]` 作为空闲表表头，
   `CURSOR_NULL` 等价于 `NULL`。代价是**容量必须预先固定**，空间耗尽即真溢出；
3. **双链表的哨兵**（`list_doubly.c`）：头哨兵的 `prev/next` 自指成环，
   于是「表头/表尾/空表」三种情况的判断全部消失；
4. **数组栈的倍增扩容**：单次 Push 可能 O(N)，但连续 N 次 Push 的总代价是
   `1+2+4+…+N < 2N`，故**摊还 O(1)**（第 11 章摊还分析的前置结论）；
5. **循环数组队列的容量问题**（`queue_circular.c`）：若只用 `front/rear` 两个下标，
   「空」和「满」的判据相同（`front == rear`），必须浪费一个槽位或增加 `size` 字段。
   本实现用 `size` + 倍增扩容，既不多浪费槽位，也不会出现「数组没满但入队失败」。

## 后缀（逆波兰）表达式求值（英文 2e 编号 3.22）

> 编号注意：本仓库的代码文件名一律用主题名，编号差异见 `../NUMBERING.md`。

实现：`postfix_eval.c`。**算法**：

1. 从左到右扫描；
2. 读到操作数 → 压栈；
3. 读到运算符 → 弹出两个操作数（先弹出的是**右**操作数），运算后把结果压栈；
4. 扫描结束栈中应**恰好剩一个**数，即为答案。

**正确性**：后缀表达式天然是后序遍历，栈中保存的正是「已求值但尚未被使用的子表达式值」。
测试覆盖：`1 2 3 * +` = 7、`7 2 /` = 3.5、`2 3 2 ^ ^` = 512、除零报错、操作数不足报错、空串报错。

## 中缀 → 后缀 / 后缀 → 中缀（英文 2e 编号 3.23）

实现：`infix_to_postfix.c`（`infix_to_postfix` 与 `postfix_to_infix`）。

**中缀转后缀算法**（运算符栈）：

- 操作数：立即输出；
- `(`：直接压栈；
- `)`：不断弹栈输出，直到遇到 `(`，并把 `(` 丢弃；若栈空仍未遇到 `(`，说明括号不匹配；
- 运算符 op：当栈顶运算符优先级 **严格大于** op（或优先级相等且 op 为**左结合**）时弹栈输出，
  然后 op 入栈；
- 扫描结束：把栈中剩余运算符全部弹出输出；若还剩 `(`，括号不匹配。

**关键细节**：
- `^` 是**右结合**：`2^3^2 = 2^(3^2) = 512`，所以优先级相等的 `^` 不能弹栈。
  测试断言 `2 ^ 3 ^ 2` 转换为 `2 3 2 ^ ^`；
- 优先级：`+ −` = 1，`* /` = 2，`^` = 3；一元负号需要单独规则（教材习题的常见扩展）；
- 支持多位数/小数：连续读取数字字符作为一个操作数（测试覆盖 `12 + 345`）。

**后缀转中缀**（反方向）：把操作数压栈；遇到运算符时弹出 b、a，构造 `(a op b)` 再压栈，
最终栈中字符串即为**完全括号化**的中缀表达式。例：`1 2 + 3 *` → `((1 + 2) * 3)`。

**中缀→后缀→求值 的往返测试**：`(2 + 3) * (4 − 1) ^ 2` → 后缀 → 求值得 45。

## 用一个数组实现两个栈（英文 2e 编号 3.24）

实现：`two_stacks.c`。**答案**：让两个栈从数组**两端向中间**生长：

- 栈 0 从下标 0 向右，`top_left` 初值 −1；
- 栈 1 从下标 `capacity−1` 向左，`top_right` 初值 `capacity`；
- **仅当 `top_left + 1 == top_right`**（即每一个槽位都被占用）时才报溢出。

**为什么这是最优的**：两个栈共享整个数组，只有当**总元素数等于数组容量**时才会失败；
不会出现「一个栈满了而另一侧大片空闲」导致的过早溢出。

**必须指出的代价**：溢出现在是「整个数组满」，无法通过扩容单个栈来解决——
要动态扩容就得整体搬家并重新分配两个栈的地址。因此它适用于**容量已知**的场景
（这正是题目要求「should not declare an overflow unless every slot is used」的隐含前提）。
测试：容量 4、两栈各 2 个元素时 `ts_is_full` 为真，再 push 返回 −1；
弹出一个后立刻可以再压入。

## 带 FindMin 的栈，以及加入 DeleteMin 后的 Ω(log N) 下界

（英文 2e 编号 3.25 a/b；**你的版本编号 3.22 a/b**。实现见 `min_stack.c`）

### a. 支持 Push、Pop、FindMin，且三者都 O(1)

**思路**：每个结点多存一个字段 `min_below`，表示「从栈底到本结点（含）为止的最小元素」。

- `Push(x)`：新结点的 `min_below = min(x, 旧栈顶.min_below)`；
- `Pop()`：弹出栈顶结点；
- `FindMin()`：返回 `栈顶.min_below`。

**为什么这是对的**：栈是 LIFO，任意时刻栈中元素恰好构成一条「从栈底到栈顶」的**前缀链**。
前缀最小值可以在入栈时逐层算好，出栈时**自动回退**到上一个前缀最小值，
所以 `FindMin` 不需要任何扫描或比较。

**复杂度**：三个操作都是 O(1)；每个元素多一个 int 字段，总空间 O(N)。

**等价的第二种实现（辅助最小值栈）**：主栈之外再维护一个 `min_stack`。
`Push(x)` 时若 `min_stack` 为空或 `x ≤ min_stack.top`，则把 x 也压入 `min_stack`；
`Pop()` 时若弹出的元素等于 `min_stack.top`，则 `min_stack` 也弹出一个；
`FindMin()` 返回 `min_stack.top`。同样 O(1)/O(N)，且 `min_stack` 通常比主栈浅。

> 易错点：判等必须用 `≤`（入栈时）配合 `==`（出栈时）。若入栈用 `<`，
> 重复的最小值只会被记录一次，弹出第一个之后 `FindMin` 就会返回错误的次小值。
> `tests/test_ch03.c` 专门用「5,3,3,7」序列覆盖了这个陷阱。

### b. 加入 DeleteMin 后，至少有一种操作必须 Ω(log N)

**证明（归约到第 7 章的排序下界，比较模型）**：

1. 反设四种操作 `Push / Pop / FindMin / DeleteMin` 的最坏情况时间都是 `o(log N)`（注意是严格的 o，不是 O）。
2. 取任意 N 个待排序的数，用这个结构来排序：
   - 依次 `Push` 全部 N 个数：代价 `N · o(log N) = o(N log N)`；
   - 重复 N 轮：`FindMin` 取出当前最小元并输出，再 `DeleteMin` 把它删掉：
     代价 `2N · o(log N) = o(N log N)`。
3. 于是我们在 `o(N log N)` 内完成了对 N 个元素的排序。
4. 但第 7 章已证：任何**基于比较**的排序算法，最坏情况下至少需要 `Ω(N log N)` 次比较
   （决策树有 `N!` 个叶子，深度至少 `log₂(N!) = Ω(N log N)`）。
5. 矛盾。故 `Push / Pop / FindMin / DeleteMin` 中至少有一个的最坏情况代价是 `Ω(log N)`。∎

**必须补充的三点**：

1. **下界限定在比较模型**。如果允许利用元素的值域做非比较操作（桶、位向量等），
   该下界不再成立——例如值域为 `[0, U)` 时可用位向量维护「下一个最小元」，
   但需要 `Ω(U)` 空间，而且已经不是比较模型。
2. **这个下界是紧的**：第 6 章的二叉堆以 O(log N) 完成 `Push`、`Pop`、`DeleteMin`，
   并以 O(1) 完成 `FindMin`（堆顶就是最小值）。所以「至少一个 Ω(log N)」不能再改进，
   同时也不存在四种操作全 O(1) 的方案。
3. **a 中的 O(1) 技巧为什么被 DeleteMin 破坏**：`min_below` 依赖 LIFO 顺序，
   即「要删除的一定是最后压入的那个」。而 `DeleteMin` 删除的位置由元素的**值**决定，
   可能在栈的任意深度；删掉中间的最小元之后，新的最小值变成「次小元」，
   而次小元的信息并没有被前缀最小值链路保存下来。
   换句话说：**只读的 FindMin 便宜，一旦允许按值删除，就必须维护动态有序信息**
   —— 这正是多出来的那个 log 因子的来源。

## Josephus 问题

实现：`josephus.c`，两种解法互相验证：

1. **循环链表模拟**：O(N·m) 时间。构建 1…N 的环，维护 `prev/cur`，每轮走 m−1 步，
   摘除 `cur` 并从下一个人重新计数；
2. **递推 O(N) 时间、O(1) 空间**：

```
J(1) = 0                          （0 起始编号）
J(n) = (J(n−1) + m) mod n
答案 = J(n) + 1                   （转成 1 起始）
```

**推导直觉**：删掉第 m 个人后，剩下的 n−1 个人重新编号成一个规模 n−1 的子问题，
再把编号映射回原编号（整体偏移 m）。

测试对 `1 ≤ n ≤ 30`、`1 ≤ m ≤ 12` 的全部组合对拍两种解法（360 组），
并固定验证 `J(5,2)=3`、`J(7,3)=4`。

## 自组织表（move-to-front / transpose）

实现：`list_array.c` 中的 `lso_find_move_to_front`、`lso_find_transpose`。

- **移到最前（move-to-front）**：访问 x 后把 x 移到表头，命中元素下次查找是 O(1)；
  对「访问局部性强」的序列效果好，但对「循环访问」是灾难性的（每次命中的元素都被推到
  别的元素前面，循环规模的访问会不断互相顶替）；
- **交换相邻（transpose）**：把 x 与它的前驱交换，只前进一格。收敛慢但更稳定，
  在循环访问模式下表现优于 move-to-front。

两者都只改变元素次序、不改变元素集合；测试覆盖命中、已命中在首位、未命中（返回 −1）三种情况。

## 有序表的求交与求并

实现：`list_ops.c`，两个游标同步推进的单遍扫描（merge 模式），O(N+M)：

- 相等 → 输出一次，双指针同时前进；
- 小的那个 → 前进该指针（求并时同时输出该元素）；
- 求并时用「与前一个输出相同则跳过」来去重。

测试表：`{1,3,5,7,9}` 与 `{3,4,5,5,10}` → 交 `{3,5}`，并 `{1,3,4,5,7,9,10}`。
（若要求「多重集语义」（保留重数），去掉去重分支即可；交集则输出 `min(count_a, count_b)` 次。）

## 链表的循环检测与断开

实现：`list_linked.c` 中的 `lil_has_loop`（Floyd 判圈）与 `lil_break_loop`。

- **判圈**：快慢指针，若相遇则有环，O(N) 时间、O(1) 空间
  （哈希表法是 O(N) 空间，另一种答案）；
- **断环**：相遇后把慢指针重置到表头，两指针同速前进，**再次相遇处即环的起点**；
  再沿环走一圈找到起点的前驱并把它的 `next` 置空。

测试流程：构造 `(2,4,1)`，把表尾接回下标 1 的结点 → `lil_has_loop` 返回 1 →
`lil_break_loop` 后返回 0，且元素次序与表长保持不变。

## 多项式 ADT

实现：`polynomial.c`。`coeff[i]` 表示 x^i 的系数（稠密表示）：

- `poly_add`：系数逐项相加，O(max(degA, degB))；
- `poly_mul`：双重循环，O(degA · degB) 次乘加；
- `poly_eval`：Horner 法则，O(deg)；
- `poly_create` 会**裁掉最高位的零系数**，使 `degree` 始终有意义（零多项式 degree 为 0）。

测试：`(1+2x+3x²) + (−1+x) = 3x+3x²`；`(1+2x+3x²)(−1+x) = −1 −x −x² + 3x³`；
零系数多项式 `0x²` 被裁为常数 0。

**另一种表示**（列表版，教材也要求过）：只存非零项 `(系数, 指数)`，乘法变成
「非零项两两相乘后按指数合并」，适合**稀疏**多项式；稠密数组在稀疏情形下会做大量无用乘法。

## 栈/队列的应用清单（本章习题常见出题点）

| 题目 | 解法要点 |
|------|----------|
| 括号匹配（`balanced_symbols.c`） | 遇左括号入栈；遇右括号与栈顶匹配并弹出；结束时栈必须为空。O(N) |
| 十进制转其他进制 | 反复取余压栈，最后全部弹出即是结果（低位先出） |
| 后缀求值 | 见 3.22 |
| 中缀转后缀 | 见 3.23 |
| 队列实现层序遍历 | 见第 4 章 BFS/层次遍历 |
| 双端队列 | 循环数组中同时支持两端插删，用 `front/size` 实现即可 |
| 用两个栈实现队列 | 入队压 `in` 栈；出队时若 `out` 栈空，把 `in` 全部倒入 `out`，然后弹出。摊还 O(1) |
| 用两个队列实现栈 | 入栈压到非空队列；出栈把非空队列的 n−1 个元素倒入另一队列，再弹出最后一个。O(N) |

## 本章易错点小结

1. 链表删除必须拿到**前驱**（单链表），这正是双链表与「哨兵」存在的理由；
2. 数组栈/队列扩容时，切勿假设「容量等于元素个数」——队列扩容要把环形数据**展开**到新数组
   的连续区间（`que_grow` 就是做这件事）；
3. 后缀求值弹出两个操作数时顺序是 `b = pop(); a = pop();`，写成 `a` 先弹会得到 `b−a` 而不是 `a−b`；
4. 中缀转后缀要区分**结合性**，`^` 右结合、`+ − * /` 左结合；
5. 游标实现里忘记把释放的结点挂回空闲表，会导致空间池只减不增（本仓库测试专门覆盖了这一点）。
