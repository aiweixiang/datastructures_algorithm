# 第 3 章 表、栈和队列 —— 习题解答

> 编号按第 2 版；每处同时标注主题。实现分别在同目录下各 `.c` 文件，
> 由 `tests/test_ch03.c`（713 条断言）验证。

## 本章核心结论：三种表实现的取舍

| 操作 | 顺序表（数组） | 单链表（带头结点） | 游标（数组模拟链表） | 双链表（带哨兵） |
|------|----------------|--------------------|----------------------|------------------|
| `Find(x)` | O(N) | O(N) | O(N) | O(N) |
| `FindKth(k)` | **O(1)** | O(N) | O(N) | O(min(k, N−k)) |
| `Insert`（已知位置） | O(N)（元素后移） | **O(1)** | **O(1)** | **O(1)** |
| `Delete`（已知结点） | O(N) | O(N)（需前驱） | O(N) | **O(1)** |
| 额外空间 | 可能预留过量 | 每元素 1 个指针 | 每元素 1 个索引 + 固定空间池 | 每元素 2 个指针 |
| 扩容/溢出 | 需要 realloc（倍增） | 无上限 | **会真正溢出**（空间池用尽） | 无上限 |
| 主要优点 | 随机访问、缓存友好 | 插入删除灵活 | 无指针/可持久保存到文件 | 双向遍历、删除 O(1) |

**要点答案**：
1. **为什么单链表带一个「头结点」**：把「在第一个位置插入/删除」这一特殊情况消掉，
   所有 `Insert` 都变成「在某个结点之后插入」，代码无需分支判断（见 `list_linked.c`）；
2. **游标实现的意义**（`list_cursor.c`）：在没有指针、或需要把结构整体持久化到文件/
   共享内存的场景下，用数组下标代替指针；`space[0]` 作为空闲表表头，
   `CURSOR_NULL` 等价于 `NULL`。代价是**容量必须预先固定**，空间耗尽即真溢出；
3. **双链表的哨兵**（`list_doubly.c`）：头哨兵的 `prev/next` 自指成环，
   于是「表头/表尾/空表」三种情况的判断全部消失；
4. **数组栈的倍增扩容**：单次 Push 可能 O(N)，但连续 N 次 Push 的总代价是
   `1+2+4+…+N < 2N`，故**摊还 O(1)**（第 11 章摊还分析的前置结论）；
5. **循环数组队列的容量问题**（`queue_circular.c`）：若只用 `front/rear` 两个下标，
   「空」和「满」的判据相同（`front == rear`），必须浪费一个槽位或增加 `size` 字段。
   本实现用 `size` + 倍增扩容，既不多浪费槽位，也不会出现「数组没满但入队失败」。

## 后缀（逆波兰）表达式求值（英文 2e 编号 3.22）

> 编号注意：本仓库的代码文件名一律用主题名，编号差异见 `../NUMBERING.md`。

实现：`postfix_eval.c`。**算法**：

1. 从左到右扫描；
2. 读到操作数 → 压栈；
3. 读到运算符 → 弹出两个操作数（先弹出的是**右**操作数），运算后把结果压栈；
4. 扫描结束栈中应**恰好剩一个**数，即为答案。

**正确性**：后缀表达式天然是后序遍历，栈中保存的正是「已求值但尚未被使用的子表达式值」。
测试覆盖：`1 2 3 * +` = 7、`7 2 /` = 3.5、`2 3 2 ^ ^` = 512、除零报错、操作数不足报错、空串报错。

## 中缀 → 后缀 / 后缀 → 中缀（英文 2e 编号 3.23）

实现：`infix_to_postfix.c`（`infix_to_postfix` 与 `postfix_to_infix`）。

**中缀转后缀算法**（运算符栈）：

- 操作数：立即输出；
- `(`：直接压栈；
- `)`：不断弹栈输出，直到遇到 `(`，并把 `(` 丢弃；若栈空仍未遇到 `(`，说明括号不匹配；
- 运算符 op：当栈顶运算符优先级 **严格大于** op（或优先级相等且 op 为**左结合**）时弹栈输出，
  然后 op 入栈；
- 扫描结束：把栈中剩余运算符全部弹出输出；若还剩 `(`，括号不匹配。

**关键细节**：
- `^` 是**右结合**：`2^3^2 = 2^(3^2) = 512`，所以优先级相等的 `^` 不能弹栈。
  测试断言 `2 ^ 3 ^ 2` 转换为 `2 3 2 ^ ^`；
- 优先级：`+ −` = 1，`* /` = 2，`^` = 3；一元负号需要单独规则（教材习题的常见扩展）；
- 支持多位数/小数：连续读取数字字符作为一个操作数（测试覆盖 `12 + 345`）。

**后缀转中缀**（反方向）：把操作数压栈；遇到运算符时弹出 b、a，构造 `(a op b)` 再压栈，
最终栈中字符串即为**完全括号化**的中缀表达式。例：`1 2 + 3 *` → `((1 + 2) * 3)`。

**中缀→后缀→求值 的往返测试**：`(2 + 3) * (4 − 1) ^ 2` → 后缀 → 求值得 45。

## 用一个数组实现两个栈（英文 2e 编号 3.24）

实现：`two_stacks.c`。**答案**：让两个栈从数组**两端向中间**生长：

- 栈 0 从下标 0 向右，`top_left` 初值 −1；
- 栈 1 从下标 `capacity−1` 向左，`top_right` 初值 `capacity`；
- **仅当 `top_left + 1 == top_right`**（即每一个槽位都被占用）时才报溢出。

**为什么这是最优的**：两个栈共享整个数组，只有当**总元素数等于数组容量**时才会失败；
不会出现「一个栈满了而另一侧大片空闲」导致的过早溢出。

**必须指出的代价**：溢出现在是「整个数组满」，无法通过扩容单个栈来解决——
要动态扩容就得整体搬家并重新分配两个栈的地址。因此它适用于**容量已知**的场景
（这正是题目要求「should not declare an overflow unless every slot is used」的隐含前提）。
测试：容量 4、两栈各 2 个元素时 `ts_is_full` 为真，再 push 返回 −1；
弹出一个后立刻可以再压入。

## 带 FindMin 的栈，以及加入 DeleteMin 后的 Ω(log N) 下界

（英文 2e 编号 3.25 a/b；**你的版本编号 3.22 a/b**。实现见 `min_stack.c`）

### a. 支持 Push、Pop、FindMin，且三者都 O(1)

**思路**：每个结点多存一个字段 `min_below`，表示「从栈底到本结点（含）为止的最小元素」。

- `Push(x)`：新结点的 `min_below = min(x, 旧栈顶.min_below)`；
- `Pop()`：弹出栈顶结点；
- `FindMin()`：返回 `栈顶.min_below`。

**为什么这是对的**：栈是 LIFO，任意时刻栈中元素恰好构成一条「从栈底到栈顶」的**前缀链**。
前缀最小值可以在入栈时逐层算好，出栈时**自动回退**到上一个前缀最小值，
所以 `FindMin` 不需要任何扫描或比较。

**复杂度**：三个操作都是 O(1)；每个元素多一个 int 字段，总空间 O(N)。

**等价的第二种实现（辅助最小值栈）**：主栈之外再维护一个 `min_stack`。
`Push(x)` 时若 `min_stack` 为空或 `x ≤ min_stack.top`，则把 x 也压入 `min_stack`；
`Pop()` 时若弹出的元素等于 `min_stack.top`，则 `min_stack` 也弹出一个；
`FindMin()` 返回 `min_stack.top`。同样 O(1)/O(N)，且 `min_stack` 通常比主栈浅。

> 易错点：判等必须用 `≤`（入栈时）配合 `==`（出栈时）。若入栈用 `<`，
> 重复的最小值只会被记录一次，弹出第一个之后 `FindMin` 就会返回错误的次小值。
> `tests/test_ch03.c` 专门用「5,3,3,7」序列覆盖了这个陷阱。

### b. 加入 DeleteMin 后，至少有一种操作必须 Ω(log N)

**证明（归约到第 7 章的排序下界，比较模型）**：

1. 反设四种操作 `Push / Pop / FindMin / DeleteMin` 的最坏情况时间都是 `o(log N)`（注意是严格的 o，不是 O）。
2. 取任意 N 个待排序的数，用这个结构来排序：
   - 依次 `Push` 全部 N 个数：代价 `N · o(log N) = o(N log N)`；
   - 重复 N 轮：`FindMin` 取出当前最小元并输出，再 `DeleteMin` 把它删掉：
     代价 `2N · o(log N) = o(N log N)`。
3. 于是我们在 `o(N log N)` 内完成了对 N 个元素的排序。
4. 但第 7 章已证：任何**基于比较**的排序算法，最坏情况下至少需要 `Ω(N log N)` 次比较
   （决策树有 `N!` 个叶子，深度至少 `log₂(N!) = Ω(N log N)`）。
5. 矛盾。故 `Push / Pop / FindMin / DeleteMin` 中至少有一个的最坏情况代价是 `Ω(log N)`。∎

**必须补充的三点**：

1. **下界限定在比较模型**。如果允许利用元素的值域做非比较操作（桶、位向量等），
   该下界不再成立——例如值域为 `[0, U)` 时可用位向量维护「下一个最小元」，
   但需要 `Ω(U)` 空间，而且已经不是比较模型。
2. **这个下界是紧的**：第 6 章的二叉堆以 O(log N) 完成 `Push`、`Pop`、`DeleteMin`，
   并以 O(1) 完成 `FindMin`（堆顶就是最小值）。所以「至少一个 Ω(log N)」不能再改进，
   同时也不存在四种操作全 O(1) 的方案。
3. **a 中的 O(1) 技巧为什么被 DeleteMin 破坏**：`min_below` 依赖 LIFO 顺序，
   即「要删除的一定是最后压入的那个」。而 `DeleteMin` 删除的位置由元素的**值**决定，
   可能在栈的任意深度；删掉中间的最小元之后，新的最小值变成「次小元」，
   而次小元的信息并没有被前缀最小值链路保存下来。
   换句话说：**只读的 FindMin 便宜，一旦允许按值删除，就必须维护动态有序信息**
   —— 这正是多出来的那个 log 因子的来源。

## Josephus 问题

实现：`josephus.c`，两种解法互相验证：

1. **循环链表模拟**：O(N·m) 时间。构建 1…N 的环，维护 `prev/cur`，每轮走 m−1 步，
   摘除 `cur` 并从下一个人重新计数；
2. **递推 O(N) 时间、O(1) 空间**：

```
J(1) = 0                          （0 起始编号）
J(n) = (J(n−1) + m) mod n
答案 = J(n) + 1                   （转成 1 起始）
```

**推导直觉**：删掉第 m 个人后，剩下的 n−1 个人重新编号成一个规模 n−1 的子问题，
再把编号映射回原编号（整体偏移 m）。

测试对 `1 ≤ n ≤ 30`、`1 ≤ m ≤ 12` 的全部组合对拍两种解法（360 组），
并固定验证 `J(5,2)=3`、`J(7,3)=4`。

## 自组织表（move-to-front / transpose）

实现：`list_array.c` 中的 `lso_find_move_to_front`、`lso_find_transpose`。

- **移到最前（move-to-front）**：访问 x 后把 x 移到表头，命中元素下次查找是 O(1)；
  对「访问局部性强」的序列效果好，但对「循环访问」是灾难性的（每次命中的元素都被推到
  别的元素前面，循环规模的访问会不断互相顶替）；
- **交换相邻（transpose）**：把 x 与它的前驱交换，只前进一格。收敛慢但更稳定，
  在循环访问模式下表现优于 move-to-front。

两者都只改变元素次序、不改变元素集合；测试覆盖命中、已命中在首位、未命中（返回 −1）三种情况。

## 有序表的求交与求并

实现：`list_ops.c`，两个游标同步推进的单遍扫描（merge 模式），O(N+M)：

- 相等 → 输出一次，双指针同时前进；
- 小的那个 → 前进该指针（求并时同时输出该元素）；
- 求并时用「与前一个输出相同则跳过」来去重。

测试表：`{1,3,5,7,9}` 与 `{3,4,5,5,10}` → 交 `{3,5}`，并 `{1,3,4,5,7,9,10}`。
（若要求「多重集语义」（保留重数），去掉去重分支即可；交集则输出 `min(count_a, count_b)` 次。）

## 链表的循环检测与断开

实现：`list_linked.c` 中的 `lil_has_loop`（Floyd 判圈）与 `lil_break_loop`。

- **判圈**：快慢指针，若相遇则有环，O(N) 时间、O(1) 空间
  （哈希表法是 O(N) 空间，另一种答案）；
- **断环**：相遇后把慢指针重置到表头，两指针同速前进，**再次相遇处即环的起点**；
  再沿环走一圈找到起点的前驱并把它的 `next` 置空。

测试流程：构造 `(2,4,1)`，把表尾接回下标 1 的结点 → `lil_has_loop` 返回 1 →
`lil_break_loop` 后返回 0，且元素次序与表长保持不变。

## 多项式 ADT

实现：`polynomial.c`。`coeff[i]` 表示 x^i 的系数（稠密表示）：

- `poly_add`：系数逐项相加，O(max(degA, degB))；
- `poly_mul`：双重循环，O(degA · degB) 次乘加；
- `poly_eval`：Horner 法则，O(deg)；
- `poly_create` 会**裁掉最高位的零系数**，使 `degree` 始终有意义（零多项式 degree 为 0）。

测试：`(1+2x+3x²) + (−1+x) = 3x+3x²`；`(1+2x+3x²)(−1+x) = −1 −x −x² + 3x³`；
零系数多项式 `0x²` 被裁为常数 0。

**另一种表示**（列表版，教材也要求过）：只存非零项 `(系数, 指数)`，乘法变成
「非零项两两相乘后按指数合并」，适合**稀疏**多项式；稠密数组在稀疏情形下会做大量无用乘法。

## 3.2 PrintLots：按位置列表打印链表元素

实现：`print_lots.c`，两个版本（测试断言两者输出完全一致）：

| 版本 | 做法 | 时间 | 前提 |
|------|------|------|------|
| `print_lots_simple` | 对 P 中每个位置各自走一遍链表 | O(\|P\|·\|L\|) | 无 |
| `print_lots_linear` | L 与 P **同步单遍推进** | **O(\|L\| + \|P\|)** | P 必须升序 |

**线性版的关键**：维护一个游标 `cur` 及其位置 `index`，指针**总体只向前走一次**：
对 P 中的下一个位置 p，把 cur 前进到第 p 个结点即可，不必从头再走。
若 P 未排序，必须先排序（O(|P| log |P|)），否则游标无法回退。

**边界**：越界位置被跳过并计数返回（`*skipped`）；两种版本对越界位置的处理一致。
位置约定是 **1 起始**（与题意一致）。这也是"用两个游标同步扫描"这一技巧的第一次出场，
后面有序表求交并（3.4/3.5）用的是同一个套路。

## 3.8 多项式的幂

实现：`poly_pow`（`polynomial.c`）。

**朴素做法**：连续乘 n−1 次，每次 O(deg²) ⇒ O(deg²·n)。
**二进制幂**：把 n 按二进制分解，平方 + 选择相乘 ⇒ 只需 O(log n) 次多项式乘法
⇒ **O(deg² · log n)**。

```c
result = 1;  base = p;
while (n > 0) {
    if (n & 1) result = result * base;
    n >>= 1;
    if (n > 0) base = base * base;
}
```

**验证**：对 n = 0..12 与"反复相乘"的朴素结果逐系数比对，
并用 `(1+x)^n` 在 x = 1 处求值等于 2ⁿ 做交叉验证（n ≤ 12 时二项式系数不会溢出）。
注意 `p^0 = 1`（常数多项式 1）是必须处理的边界。

## 3.9 任意精度整数运算包

实现：`bignum.c`（`BigInt` 不透明类型）。

**表示**：十进制位数组（小端，`dig[0]` 是个位）+ 符号（−1/0/+1）。
用十进制位而不是 `base 2³²` 是为了让打印、解析、进位逻辑与人类直觉一致；
工程实现通常用 `base 10⁹`（每个 limb 存 9 位十进制）以兼顾可读性与常数。

**算法与复杂度**（N、M 为位数）：

| 运算 | 算法 | 复杂度 |
|------|------|--------|
| 加减 | 逐位带进位/借位，先比绝对值定符号 | O(max(N,M)) |
| 乘法 | 教科书竖式（双重循环） | O(N·M) |
| 比较 | 先比长度再逐位比 | O(N) |

**测试（都能算出来，不靠记忆常数）**：
- `2^100 = 1267650600228229401496703205376` ✅（已知十进制串）；
- `20! = 2432902008176640000`，与 64 位算术对拍 ✅；
- `100!` 的十进制串末尾恰好 **24 个 0**，与 `⌊100/5⌋ + ⌊100/25⌋ = 24` 一致 ✅
  （尾零个数是独立于实现的数学事实，很适合当交叉验证）；
- 300 组随机 ±10⁹ 的加减乘与 `long long` 逐字符对拍 ✅。

**与 2.20 的联系**：这题正是"整数并非天然固定字长"的实证——
`2^100` 用任何 64 位类型都会溢出，必须自己管位数。真实库（GMP 等）在此之上还用了
Karatsuba（O(N^1.585)）、Toom-Cook 和 FFT（O(N log N)）乘法。

## 3.11 递归与非递归的链表查找

实现：`lil_find`（迭代）与 `lil_find_recursive`（递归，`list_linked.c`）。

两者**时间复杂度相同**（都是 O(N)，最坏走完整条链），差别在空间与工程风险：

| | 时间 | 额外空间 | 风险 |
|--|------|----------|------|
| 迭代 | O(N) | **O(1)** | 无 |
| 递归 | O(N) | **O(N)**（栈帧） | 长链表会**爆栈** |

测试断言两者返回的是**同一个结点指针**（不只是相同元素），并覆盖了
空表、目标在首位、目标不存在、以及传入 NULL 表的四种情形。

> 结论：线性结构上的查找没有任何理由用递归——递归的收益（代码短）远小于
> 栈空间与栈溢出的代价。第 4 章的树结构则相反，递归天然契合树形定义。

## 3.13 基数排序学生记录

实现：`radix_sort_records`（`radix_records.c`），LSD（最低位优先）十进制桶排序。

**算法**：对每一位（个位、十位、…）做一趟**稳定**的计数排序。
位数 P = 最大关键字的十进制位数，故时间 **O(P·(N + 10))**，空间 O(N + 10)。
P 是常数时是线性时间（这也是教材把它放在第 3 章的理由：它不需要比较）。

**为什么必须稳定**：低位排序的结果必须被后续高位排序"继承"。
若某趟不稳定，低位已确定的相对次序会被打乱，最终结果出错。
测试专门验证：关键字相同的记录（如 `{17,"a"}` 与 `{17,"c"}`）在排序后
**保持输入的相对次序**（"a" 仍在 "c" 前），并且 1000/999/0 这类跨位数关键字排序正确。

**记录版与纯数字版的区别**：排序时整条记录跟着关键字一起搬移（而不是只排关键字索引），
所以 `struct` 的赋值成本要计入常数因子；若记录很大，改成"排序索引数组 + 间接访问"更划算。

## 3.14 把图读入邻接表（链表版与游标版）

实现：`adjacency.c`，两种表示并存并交叉验证。

| | 链表版 `AdjGraph` | 游标版 `CursorAdjGraph` |
|--|-------------------|-------------------------|
| 结构 | `head[1..N]` 指向 `malloc` 的结点 | `head[1..N]` + 边数组 `edges[1..E]`（`next` 是下标） |
| 加边 | O(1) 头插 | O(1) 头插 |
| 容量 | 无上限 | **必须预先给定**，用尽即报错 |
| 遍历 | 指针解引用 | 数组索引（缓存友好，可整体持久化） |
| 空间 | 每边 1 指针 + 对齐开销 | 每边 3 个 int |

**输入格式**：每行 `u v [w]`，`w` 省略时默认 1，`#` 与空行忽略，按**无向图**读入
（每条边存两个方向）。顶点编号 **1..N**（教材风格）。

**测试**：同一张 4 顶点 5 边的乱序输入，分别建两种结构，
逐邻接项比对顶点与权重**以及顺序**；另外验证
游标的边数组用尽会返回 −1（这是它与链表版的关键差别），以及非法顶点被拒绝。

> **踩过的坑（值得写进答案）**：游标实现里"空"必须用 `CURSOR_NULL = −1`，
> 而 **0 是本实现中合法的边下标**。若把 `head[v]` 的初值留在 `calloc` 的 0，
> 遍历会走到未初始化的 `edges[0]`——这个错误是 ASan 在测试里抓出来的。

## 3.16 删除数组中的重复元素

实现：`array_dedup.c`。

| 版本 | 时间 | 额外空间 | 是否保持首次出现顺序 |
|------|------|----------|----------------------|
| `remove_duplicates_slow` | O(N²) | O(1) | ✅ 保持 |
| `remove_duplicates_sort` | O(N log N) | O(1)（原地排序） | ❌ 顺序被破坏 |
| 散列版（第 5 章） | **O(N)** | O(N) | ✅ 保持 |

**慢版的写法**：维护输出长度 m，对每个元素检查它是否已出现在 `a[0..m-1]`——
即"用已输出的前缀当集合"。这样不需要额外数组，但每次检查是 O(m)。

**排序版**：先 `qsort` 再线性去重（`a[i] != a[m-1]` 才保留）。

测试：300 组随机数组断言两版**得到的集合完全相同**，并固定验证
`{3,1,3,2,1,3,5}` → 慢版 `{3,1,2,5}`（保序）、排序版 `{1,2,3,5}`。

## 3.17 实现懒惰删除并分析优缺点

实现：`lazy_list.c`。

**做法**：删除时只把该槽位标记 `deleted`（不搬移数据）；插入时**优先复用**已删除槽位；
当"已删除个数 > 存活个数"（代码里用 `live * 2 < size`）时执行一次 `compact` 真正压实。

**摊还分析（本题的核心）**：
一次 compact 的代价是 O(size)，但它把"垃圾比例"从 ≥ 1/2 降到 0；
两次 compact 之间至少发生了相当于"存活数"的删除次数，
所以把 compact 的代价摊到每次删除上是 **O(1)** 摊还。

**优点**：删除 O(1)，不必搬运大对象（对象很大时收益显著，比如几百字节的结点）。
**缺点**：每个元素多一个标记位/字节；`find` 必须跳过已删除项（最坏仍 O(N)，
且常数变大）；元素计数会虚高，遍历时要额外判断；内存峰值偏高。
**典型适用**：删除多、查找少；或"删除的代价远高于遍历成本"的场景（如大记录表）。

测试：与朴素数组模型对拍 1500 步随机插入/删除（含重复元素），逐步校验
存活数、`find` 结果、以及删除不存在元素返回 −1；并验证槽位复用不会增加槽位总数、
大量删除后 `deleted == 0`（说明整理确实发生了）。

## 3.23 用一个数组实现三个栈

实现：`three_stacks.c`。

**做法**：把数组三等分，第 k 个栈只用第 k 段：
`base[k] = k·C/3`，`end[k] = (k+1)·C/3`，`top[k] = base[k] − 1`。
某个栈 `top[k]+1 == end[k]` 时报溢出。

**为什么做不到两栈那样"只有在所有槽位都用满时才溢出"**：
两栈时两个栈分别从两端向中间长，**两栈元素总数 = 已占用槽位数**，
所以"总满"与"某栈满"等价。三个栈时中间那个栈被两边夹住，
除非允许在数组内部搬移元素（那就不是 O(1) 了），否则无法共享空隙。
**所以本题的标准答案就是"等分三段"，代价是可能出现"虚假的满"**
（某栈已满而其他段大片空闲）。

测试：容量 9 时每栈分到 3 个槽位，段满后 push 必须返回 −1 且不影响其他段；
交错随机压弹 500 步，逐步断言每个栈的 size 不超过它分到的份额。
（更好的方案是把三个栈连成"循环双端"结构或改用第 5 章的散列/第 6 章的堆，
但那已经超出"一个数组 + O(1) 操作"的前提。）

## 3.24 分析斐波那契递归的栈空间

实现：`recursion_depth.c`（`fib_max_depth`、`fib_call_count`）。

**结论：时间指数级，空间只有 Θ(N)。**

- **调用次数**：`C(0) = C(1) = 1`，`C(n) = C(n−1) + C(n−2) + 1`，
  解得 **`C(n) = 2F(n+1) − 1 = Θ(φⁿ)`**（指数级）；
- **最大递归深度**：最深的路径是 `fib(n) → fib(n−1) → … → fib(1)`，
  恰好 **n 层**（n = 0 时 1 层）⇒ **栈空间 Θ(N)**。

**关键洞察**：递归的**时间**看递归树的**结点数**，**空间**看递归树的**深度**。
递归树按深度优先展开，同一时刻栈上只有"当前的一条路径"——
所以指数级的调用次数并不导致指数级的栈空间。
（这也解释了为什么朴素递归 fib 不会先爆内存，而是先花掉几千年时间。）

测试：`fib_max_depth(n) == n`（n ≤ 25，实际递归测量），
`fib_call_count(n) == 2F(n+1) − 1`（n ≤ 40，与迭代求出的斐波那契对拍）。

## 3.26 实现双端队列（所有操作 O(1)）

实现：`deque.c`。

**结构**：循环数组 + 倍增扩容，用 `front` 与 `size` 描述队列
（队尾下标 = `(front + size − 1) mod C`）：

```
push_front:  front = (front − 1 + C) mod C;  data[front] = x;  ++size
push_back :  data[(front + size) mod C] = x; ++size
pop_front :  v = data[front]; front = (front + 1) mod C; --size
pop_back  :  v = data[(front + size − 1) mod C]; --size
```

四个操作全是 **O(1)**（摊还；只有扩容那一瞬间是 O(N)，倍增后摊还 O(1)）。
用 `front + size` 而不是 `front/rear` 两个下标，可以让"空/满"不再歧义，
也不必像某些写法那样**浪费一个槽位**。

测试：空队列的四种操作都返回 `ELEMENT_NOT_FOUND`；
两端交错压弹与 `front/back` 读取；
100 轮"弹头压尾"验证环形回绕；最后用 50×300 步与朴素数组模型
（`model[lo..hi)`）逐步对拍四种操作。

## 本章易错点小结

1. 链表删除必须拿到**前驱**（单链表），这正是双链表与「哨兵」存在的理由；
2. 数组栈/队列扩容时，切勿假设「容量等于元素个数」——队列扩容要把环形数据**展开**到新数组
   的连续区间（`que_grow` 就是做这件事）；
3. 后缀求值弹出两个操作数时顺序是 `b = pop(); a = pop();`，写成 `a` 先弹会得到 `b−a` 而不是 `a−b`；
4. 中缀转后缀要区分**结合性**，`^` 右结合、`+ − * /` 左结合；
5. 游标实现里忘记把释放的结点挂回空闲表，会导致空间池只减不增（本仓库测试专门覆盖了这一点）。
